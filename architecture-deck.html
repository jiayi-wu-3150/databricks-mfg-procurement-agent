The job

One question, four kinds of evidence

A procurement lead gets a supplier quote and has minutes to judge it. The agent answers the real question they'd ask a team of analysts:

“Should I buy 200 tons of HDPE at $1,300/ton right now?”

Do we need it?

On-hand inventory, safety stock, days of supply, upcoming demand.

Is the timing right?

Crude-oil price and trend — resin tracks oil with a lag.

Is it a good price?

An ML model scores the deal against past outcomes.

Is it allowed?

Approval thresholds, preferred suppliers, contract terms.

The agent

A thin, resilient orchestrator

Framework

OpenAI Agents SDK Runner inside MLflow agent_server (@invoke/@stream), served on Databricks Apps.

LLM

databricks-claude-sonnet-4-5 via direct FM serving. An env flag switches to the AI Gateway on workspaces where the FM path is disabled.

Instructions

A procurement-advisor prompt that folds in three skills: oil-market-analyst, procurement-advisor, inventory-monitor.

Resilience

Each MCP server is health-checked per request; an unavailable tool is dropped so one down server can't crash a turn.

Governed guidance · Beta

Skills — loaded live from Unity Catalog

A skill is a loadable instruction sheet (SKILL.md), not a tool that does work — the model load_skills it, then follows its approach using the four tools above.

  • Three playbooks as securables — catalog.schema.skill under the schema's Skills tab: oil-market-analyst, procurement-advisor, inventory-monitor.
  • Loaded live over the managed skills MCP (/ai-gateway/skills/…), filtered to read tools (list_skills, load_skill, get_skill_files) — the agent reads skills but can't create or delete them.
  • Governed & live — agent SP granted READ_VOLUME; edit a skill and re-publish and it takes effect with no app redeploy.
  • Gotcha: skills describe tools by capability — never hardcode a bare tool name (the UC Functions MCP namespaces it to jywu__jywu_mfg_agent__get_material_status).

Every turn is traced to an MLflow experiment. Optional OpenTelemetry dual-export ships traces to an external backend without losing Databricks tracing.

Deployment

Bundles & a reproducible prep runbook

  • Agent app ships as a Databricks Asset Bundle; runtime config (model, catalog, warehouse, MCP URLs, Lakebase) lives in the bundle's config.env.
  • MCP servers deploy as separate Databricks Apps (apps create → sync → apps deploy).
  • Prep runbook (setup/README.md): data → pricing model → policy PDFs → AI-functions chunks index → UC governance (connections / services / function) → grants.

Design decisions & lessons

What shaped the build

DecisionWhy
Custom tools as MCP servers on AppsReusable across agents; lower latency than UC-function tools.
Lean model requirementsInferred deps pulled the whole venv (PySpark, 150+ pkgs) into the serving image — huge, slow build. An explicit 5-package list builds fast anywhere.
Direct FM serving, gateway by flagWorks where the FM path is enabled; one env flag adapts to workspaces where it isn't.
Managed MCP for retrievalEndorsed, internal path — no egress concerns for vector search.
No uv.lock in the deployBuild's uv version differed from local, tripping --locked; let the build resolve from pyproject.
